# Arist AI Control 远程语音使用与测试说明

适用版本：`{{VERSION}}`

## 一、运行边界

AhaKey 507C、蓝牙、麦克风、云端语音识别和文字注入都运行在笔记本本地。Tailscale 只提供到远程主机的网络路径，不传输本次录音。远程应用能否收到文字，取决于本地远程客户端是否成功把临时剪贴板和 `Ctrl+V` 传到远端。

如果微信在笔记本本地运行，Arist AI Control 可以检查本地微信窗口和输入焦点。如果微信在远程主机运行，Arist AI Control 只能看到 `mstsc.exe`、ToDesk 等本地远程客户端窗口，不能读取远程微信内部文本框。

文本轻度整理也遵循这个边界：本地 `Weixin.exe` / `WeChat.exe` 自动使用“聊天保真”模式，其他本地应用使用“工作轻度整理”模式；远程微信由于只能识别到远程客户端进程，目前会使用工作模式。不要把所有远程客户端统一设成聊天模式，因为同一远程会话内也可能正在使用 Codex、编辑器或正式文档。

## 二、安装后的预设安排

- `BLE_tcp_driver.exe` 随主程序安装并由 Arist AI Control 自动启动、检查和恢复。
- 端口 `9000` 与 `8765` 只监听 `127.0.0.1`，不通过 Tailscale 暴露。
- 文本默认使用 clipboard-first 原子粘贴，临时剪贴板最多保留约 1.5 秒，随后恢复用户原剪贴板。
- 为减少开头丢字，程序运行期间会持续读取麦克风，并只在内存中循环保留最近约 300ms（16kHz PCM16 下约 9600 字节）作为 pre-roll。空闲音频不落盘、不转写、不上传；按下语音键后才将 pre-roll 和正式录音组成识别会话。Windows 麦克风指示持续点亮属于预期行为，完全退出 Arist AI Control 后热采集随即关闭并清空缓冲。
- 长文本轻度整理采用结构化分段处理：安全片段使用 云端结果，缺失或未通过保真校验的片段单独回退原文，不再因为一个片段有风险而丢弃整段整理结果。
- `Arist-AI-Control-Remote-Template.rdp` 已启用剪贴板重定向，并关闭不需要的麦克风重定向。使用 Windows 远程桌面时，可复制模板、填写 `full address:s:` 后面的 Tailscale IP 或主机名。
- `Run-Remote-Preflight.cmd` 会检查程序、BLE 桥、.NET、蓝牙服务、Tailscale 服务、本机端口和常见远程客户端；它不会读取或输出 API Key。

## 三、开始前检查

1. AhaKey 507C 只连接当前笔记本，不要同时连接原台式机。
2. Arist AI Control 与远程客户端都使用普通用户权限运行，不要一个管理员、一个普通用户。
3. Windows 已允许桌面应用使用麦克风。
4. 远程软件已打开剪贴板同步。Windows RDP 应有 `redirectclipboard:i:1`。
5. 先点击目标输入框，再按住语音键；识别和粘贴完成前不要切换窗口、点击别处或移动光标。

## 四、四级验收

每一级都说同一句：

> 请复制粘贴这段文字，然后按 Control C，再按 Control V。

预期文本中的快捷键应规范成 `Ctrl+C` 和 `Ctrl+V`。

### A. 笔记本本地记事本

目的：验证麦克风、API Key、云端识别、AhaKey 按键和基础文本注入。

通过标准：松开语音键后，整句只出现一次，没有丢字、重复或残留错误剪贴板。

### B. 笔记本本地微信

目的：验证微信输入框与 clipboard-first 兼容性。

通过标准：文字一次性进入当前聊天输入框，原剪贴板随后恢复。

本版本已对 `Weixin.exe` / `WeChat.exe` 的 Qt 主窗口增加兼容策略：只要仍是同一微信进程和同一顶层窗口，就容忍悬浮提示或微信内部控件造成的 focused/caret 元数据变化；切换到另一个顶层窗口或另一个进程仍会安全取消。录音与粘贴完成前仍不要切换聊天、点击其他输入框或移动光标，因为同一微信主窗口内部切换聊天无法由本地顶层窗口边界可靠识别。

本地微信还会自动选择聊天保真整理：允许压缩明显的连续口吃和机械重复，并根据真实语调与明确文字线索克制恢复问号、感叹号或省略号。只有原话存在明确笑意、庆祝、认可或爱意时，才允许在整条消息末尾添加一个白名单表情；中性、严肃或不确定内容默认不加。人名和专有词由本机术语表辅助识别，聊天校验还会保护已识别出的专用姓名不被精修改字。任何结果未通过长度、字符、语气、标点或表情保真校验时，都会回退到原始转写。

### C. 远程主机记事本

目的：把远程剪贴板同步问题与微信/Codex 自身问题分开。

通过标准：远程记事本收到完整且唯一的一份文字。

若 A、B 成功而 C 失败，优先检查远程客户端的剪贴板同步、权限级别和网络延迟，不要先改 ASR。

### D. 远程微信或远程 Codex

目的：验证最终实际工作场景。

通过标准：目标应用收到完整文字，且没有发到错误会话或错误输入框。

若 C 成功而 D 失败，问题通常在远程应用自身焦点、输入法、管理员权限或安全策略。

当前版本无法从本地远程客户端窗口判断远端究竟是微信还是 Codex，因此两者都使用工作轻度整理模式。若远程微信需要聊天保真模式，应记录为后续显式开关需求，不要用进程猜测自动切换。

## 五、按失败层级定位

| 结果 | 最可能原因 | 下一步 |
|---|---|---|
| A 失败 | 蓝牙、麦克风权限、API Key、网络或本地程序 | 运行预检，先修复本地链路 |
| A 成功、B 失败 | 微信顶层窗口变化、本地权限不一致或粘贴被微信拦截 | 固定当前聊天输入框；检查日志中的目标匹配原因与粘贴结果 |
| B 成功、C 失败 | 远程剪贴板没有同步或同步慢于临时剪贴板租期 | 打开剪贴板同步；改用 RDP 模板；记录延迟 |
| C 成功、D 失败 | 远程微信/Codex 输入框、输入法或权限问题 | 用同一远程会话内的记事本对照 |
| 偶发旧文字或空粘贴 | 远程剪贴板同步过慢 | 记录远程工具、网络和失败频率，考虑增加专用远程模式 |
| 文字发到错误位置 | 录音期间切换了窗口或输入框 | 完成前不要改变焦点；保留 fail-closed 安全策略 |

## 六、反馈时需要保留的信息

- 使用的远程软件及版本：RDP、ToDesk、向日葵等；
- 微信/Codex 在本地还是远端；
- A、B、C、D 中第一个失败的层级；
- 是否出现“识别成功但无文字”“旧剪贴板”“重复文字”或“错投窗口”；
- `Arist-AI-Control-Remote-Preflight.txt`；
- Arist AI Control 对应时间段日志，但不要发送 API Key。

在没有真实测出远程剪贴板耗时前，不建议直接放宽焦点保护或无限延长剪贴板占用时间。先用四级验收定位，再决定是否增加针对特定远程软件的兼容模式。
